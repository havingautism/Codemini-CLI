# 状态栏运行时指标（Status Bar Runtime Indicators）

Status: ready-for-agent

## Problem Statement

Codemini 的终端 TUI 与 Web UI 共用一个状态栏，但当前它只显示模型、provider、上下文占用百分比与 live/idle 状态。用户（以及审视运行状态的开发者）无法一眼看出：会话进行到什么时间、工具调用了多少次、还有多少待办、运行中出过哪些错误、以及当前运行环境的完整信息。这些信息要么分散在其他面板里，要么根本看不到，迫使用户频繁切换界面或手动排查。

## Solution

把状态栏升级为一条**紧凑的运行时摘要条**：在保留原有信息的基础上，新增五类轻量指标——时间戳、工具调用计数、todo 徽章、错误记录摘要、系统环境信息。状态栏本体保持「克制」（一行、不膨胀），详细信息通过点击/悬停展开（Web 用 Popover/Dialog，TUI 用单个按键进入状态详情视图）。

所有指标来自同一份运行时状态快照（Web 与 TUI 一致），并遵守两条黄金法则：**只留摘要、不留垃圾**（错误只保留最近 3 条 ≤100 字的摘要，完整堆栈按需加载）；**冻结替换占位符**（截断占位符字节级一致，避免 KV Cache 前缀缓存失效）。

## User Stories

1. 作为 Web UI 用户，我想要在状态栏看到「最后状态更新时间」，以便判断 Agent 是否仍在工作还是已经空闲。
2. 作为 TUI 用户，我想要在状态栏看到同样的时间戳，以便在纯终端环境下也能判断运行进度。
3. 作为用户，我想要时间戳以相对时间显示（如「3 分钟前」），以便快速感知活跃程度。
4. 作为用户，我想要悬停/点击时间戳查看绝对时间，以便需要精确时间时不用猜测。
5. 作为用户，我想要一个显示「本会话工具调用总数」的徽章，以便评估 Agent 已做了多少工作。
6. 作为用户，我想要展开工具计数徽章查看「按工具类型」的明细，以便了解工作量分布。
7. 作为用户，我想要失败/被拦截的工具调用也计入计数，以便计数真实反映执行情况。
8. 作为用户，我想要一个显示「未完成/进行中 todo 数量」的徽章，以便一眼掌握剩余待办。
9. 作为用户，我想要点击 todo 徽章跳转到已有的 TodoList 面板，以便无需离开状态栏就能查看完整列表。
10. 作为用户，我想要一个显示「本会话工具失败次数」的错误徽章，以便及时发现运行中出过哪些错。
11. 作为用户，我想要展开错误徽章查看最近 3 条错误摘要（类型 + ≤100 字消息），以便快速了解失败原因。
12. 作为用户，我想要完整堆栈只在点开详情时按需加载，以便状态栏与上下文不因长堆栈而膨胀。
13. 作为用户，我想要每条错误摘要不超过 100 字，以便状态栏永远保持轻量。
14. 作为用户，我想要大文件/长内容的截断占位符在压缩与会话重建时保持字节级一致，以便 KV Cache 前缀缓存不被破坏。
15. 作为用户，我想要一个「系统」指示器，点击后弹出 9 项环境信息（平台/Node 版本/Shell/沙箱模式/项目路径/Git 分支与状态/模型/provider/执行模式），以便排查环境问题时不用翻配置。
16. 作为 TUI 用户，我想要按一个键进入「状态详情」视图集中查看五类指标，以便在没有鼠标的终端里也能展开详情。
17. 作为用户，我想要工具计数与错误摘要在上下文压缩（compact）后依然保留，以便压缩不抹掉本会话的累计统计。
18. 作为用户，我想要工具计数与错误摘要在切换会话时重置，以便不同会话的统计互不串扰。
19. 作为用户，我想要错误详情对话框提供「清空本会话错误」「自动滚动到最新」「复制堆栈」三个动作，以便管理错误历史。
20. 作为使用中文/英文界面的用户，我想要所有新标签都有双语，以便两种语言下体验一致。
21. 作为开发者，我想要这五组新字段都来自同一份运行时状态快照，以便 Web 与 TUI 行为一致、不出现两套实现。

## Implementation Decisions

- **单一数据源**：五组新字段（时间戳、工具调用计数、todo 计数、错误摘要、系统环境）全部加到现有的运行时状态快照上，Web 与 TUI 从同一处渲染。
- **新增一个会话统计累加器**：一个纯函数，在工具结束/失败/被拦截的事件上累加「按类型计数」与「有界错误摘要」。它挂载在会话对象上，因此随会话存活、在上下文压缩后仍保留、在切换会话时重置。
- **错误记录为两层表示**：常驻层只保留最近 3 条摘要（工具名 + 失败类别 + ≤100 字消息）；完整堆栈仅在用户点开详情时按需加载，绝不进入快照。
- **黄金法则一（只留摘要）**：错误摘要上限 3 条、每条消息 ≤100 字；禁止把完整 traceback 常驻到状态栏或快照。
- **黄金法则二（冻结占位符）**：截断占位符（如 `[Truncated: N lines omitted]`）在压缩与会话重建时保持字节级一致，文案不得随意改动。
- **工具计数语义**：按工具类型分组；成功、失败、被拦截均计入；随会话重置。
- **todo 徽章**：只显示「未完成 + 进行中」数量；点击跳转现有 TodoList 面板，不在状态栏内编辑。
- **系统环境信息**：共 9 个只读字段（平台、Node 版本、Shell、沙箱模式、项目路径、Git 分支与状态、模型、provider、执行模式），点击弹出、不常驻。
- **展示范式**：Web 端状态栏保持紧凑，徽章悬停/点击展开（Popover/Dialog）；TUI 端用单个按键进入状态详情视图，同时保留一行摘要。
- **时间戳**：显示「最近一次状态更新/活动」的时间，相对时间为主、绝对时间按需。
- **错误类型**：取「工具名 + 失败类别（error / blocked）」。
- **国际化**：所有新标签走 Web 端中英双语键，符合项目既有约定。

## Testing Decisions

- **以外部行为为测试边界**：只断言快照产出的字段与累加器的外部行为，不测实现细节。
- **主接缝测试**：直接调用运行时状态快照，断言五组字段（时间戳、工具计数、todo 计数、错误摘要、系统环境）正确产出——沿用现有「上下文占用」测试的先例（直接构造会话、调用快照、断言字段）。
- **累加器纯函数测试**：单测累加器的边界——最近 3 条上限、≤100 字截断、失败/被拦截均计数、占位符字节稳定、随会话重置——沿用现有纯函数测试先例。
- **覆盖平台差异**：系统环境字段的取值在 Windows / macOS / Linux 上分别验证。

## Out of Scope

- 跨会话持久化错误记录（本规格仅会话内保留）。
- 在状态栏内直接编辑 todo（只跳转面板）。
- 超出 9 项约定的系统环境字段。
- 完整堆栈常驻状态栏。
- 改动现有 CTX 占用、模型、provider 的既有展示。
- 任何对截断占位符文案的改动（占位符是冻结的）。

## Further Notes

- 两条黄金法则是硬约束，已在 `CONTEXT.md` 词汇表（错误记录、截断占位符）中记录，并由 ADR-0001 记录「截断占位符字节级冻结」的决策与理由。
- 接缝约定：两个接缝——扩展运行时状态快照（输出）+ 新增会话统计累加器（输入），尽量保持最少接缝。
