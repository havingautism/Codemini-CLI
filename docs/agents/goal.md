# 在聊天中使用 /goal

在终端或 Web 聊天里输入 `/goal`，接着用自己的话描述要完成的事。例如：

```text
/goal 从 1 数到 100
```

系统先从原话中提取验收条件，保存到会话，再开始执行。简单的连续整数数列可以直接在本地识别。若自己填写了验收条件，系统保留每一项原文和顺序，仅判断应该查看聊天回复还是工作区证据。`/goal 从1数到100 验收：在聊天中列出所有数字` 同样在聊天里交付完整数列。处理代码或文件的目标需要相应的工具证据。

有具体要求时，也可以写明验收条件、约束或轮数。用换行或中文分号分开各项验收条件。轮数默认是 5，提取条件不占执行轮次。

```text
/goal 修复 CSV 导出的中文文件名
验收：
- 导出后下载的文件名与输入的中文名称一致
- 相关回归测试通过
约束：保留现有导出接口
轮数：3
Token预算：20000
```

也可写在一行，例如 `/goal 修复 CSV 导出 验收：中文文件名正确；导出回归测试通过`。

| 需要做的事 | 聊天中输入 |
| --- | --- |
| 查看目标、验收条件、已用轮数、活动耗时、Token 用量和停止原因 | `/goal` 或 `/goal status` |
| 在运行中追加要求 | 直接发送文字，如「只改导出模块，保留原文件名」 |
| 在原会话修改目标及验收条件 | `/goal edit 只修复 CSV 导出的中文文件名` |
| 清除目标，继续在同一会话聊天或建立新目标 | `/goal clear` |
| 暂停目标的后续执行 | `/goal pause` |
| 中断后确认某项操作已生效 | `/goal resolve <操作ID> done` |
| 核对现场后允许重试某项操作 | `/goal resolve <操作ID> retry` |
| 在现有预算内恢复 | `/goal resume` |
| 增加 2 轮预算并恢复 | `/goal resume +2` |
| 增加 10000 Token 预算并恢复 | `/goal resume --add-tokens 10000` |
| 同时追加轮数和 Token | `/goal resume +2 --add-tokens 10000` |

每轮围绕未满足的验收条件执行并核查结果。遇到需要用户授权的操作，沿用会话原有的审批流程。轮数用尽后可以先检查进度，再决定是否追加。单个目标累计最多 100 轮。

修改运行中的目标会中断旧要求下正在进行的操作，按新要求重新验收。修改已暂停的目标后，可在准备好时输入 `/goal resume`。修改或清除目标都保留聊天记录和已经写入工作区的文件。

Token 预算可选。在下一次模型请求前检查预算，已经发出的请求仍可能使用额外 Token。状态显示提供方已报告的用量及未报告用量的请求数。设了 Token 预算时，若网关没有回传用量，系统会在下一次调用前暂停。已完成验收的目标保留完成状态和缺报记录。若连续三轮遇到同样的阻塞且没有取得新进展，系统也会停下并说明原因。排除问题后输入 `/goal resume`，系统会重新判断后续进展。

### 验收和恢复

主模型使用 `model.name`。对于在聊天里按顺序列出一段连续整数的简单目标，程序可以逐个对照实际回复，指出第一个缺失或不符的数字。这类目标只需一个模型。目标含其他交付要求时，请在模型设置里为 `model.fast_name` 或 `model.lite_name` 配置另一个可用模型。它会读取目标和观测，逐项核对验收条件。

每轮验收结束，聊天里会显示本轮结论和原因。Web 聊天中可以展开这条记录，查看各项引用的证据摘要和截至该轮的累计用量。

- 要证明文件内容，运行时可以记录 `read` 实际读取的路径、行号和文件哈希。要证明行为，需要对应测试或检查命令的退出状态和输出。
- 直接使用 `node --test` 时，请保留默认报告或使用 `--test-reporter=tap`，以便验收器核对实际通过数。验收指定用例时，报告应能看到对应的用例名。
- 验收记录多时，系统按条件分批核对。同一项的证据跨页时，会从各页找出有关的原文和反证，再一起判断。若一项必须核对的原文仍超出模型上下文，状态会说明原因，可以细分条件或更换验收模型。
- 文件改动后，之前版本的观察需要重新验证。缺少证据时，目标会在剩余预算内继续尝试。若验收模型配置缺失或调用失败，先修复配置，再输入 `/goal resume`。
- 会话意外退出后，重新打开同一会话，输入 `/goal` 可查看中断阶段。若有结果未知的操作，先核对操作的实际效果。比如命令已经提交工单，就用状态中显示的操作 ID 输入 `/goal resolve <操作ID> done`。确认可以安全重试时，输入 `/goal resolve <操作ID> retry`。处理完后，`/goal resume` 会接着原来的轮次执行。若仅验收中断，会先重试验收。
- 目标可以调用 `run_subagent`。暂停会中断仍在执行的子任务，已完成的交接记录保存在会话中。恢复后，主代理可以再次委派并使用新取得的证据。
- 目标会等待自己委派的子代理和需要退出的后台命令。完成事件会唤醒执行流程。等待期间可用 `/goal status` 查看进展。首次检查在 30 分钟后，随后间隔 60 分钟、120 分钟，之后每隔 120 分钟再检查。后台命令重复打印同一条等待日志，只说明进程还有活动。连续三次检查没有可确认的新进展时，系统会暂停。可在创建目标时写 `等待上限：15分钟`，限制单次等待时间。具有就绪条件的常驻服务在就绪后交还控制权。
- 审批过程中可在 Web 确认框点击「暂停目标」，终端确认框可按 Ctrl+C。恢复后，仍需授权的操作会再次请求确认。
