# 在聊天中使用 /goal

在终端或 Web 聊天里输入 `/goal`，接着用自己的话描述要完成的事。例如：

```text
/goal 从 1 数到 100
```

执行模型会先从原话中提取验收条件，保存到会话，再开始执行。这个例子直接在聊天里交付数列，独立验收模型核对完整回复。处理代码或文件的目标仍需要相应的工具证据。用 `/goal status` 可以查看保存的条件。

有具体要求时，也可以写明验收条件、约束或轮数。用换行或中文分号分开各项验收条件。轮数默认是 5，提取条件不占执行轮次。

```text
/goal 修复 CSV 导出的中文文件名
验收：
- 导出后下载的文件名与输入的中文名称一致
- 相关回归测试通过
约束：保留现有导出接口
轮数：3
```

也可写在一行，例如 `/goal 修复 CSV 导出 验收：中文文件名正确；导出回归测试通过`。

| 需要做的事 | 聊天中输入 |
| --- | --- |
| 查看当前目标、进度与停下的原因 | `/goal` 或 `/goal status` |
| 暂停目标的后续执行 | `/goal pause` |
| 在现有预算内恢复 | `/goal resume` |
| 增加 2 轮预算并恢复 | `/goal resume +2` |

每轮围绕未满足的验收条件执行并核查结果。遇到需要用户授权的操作，沿用会话原有的审批流程。轮数用尽后可以先检查进度，再决定是否追加。单个目标累计最多 100 轮。

### 验收和恢复

主模型使用 `model.name`。请在模型设置里为 `model.fast_name` 或 `model.lite_name` 配置另一个可用模型，让它独立核对每项验收标准。验收模型读取目标和机器观测，无法调用工具。

- 要证明文件内容，运行时可以记录 `read` 实际读取的路径、行号和文件哈希。要证明行为，需要对应测试或检查命令的退出状态和输出。
- 直接使用 `node --test` 时，请保留默认报告或使用 `--test-reporter=tap`，以便验收器核对实际通过数。验收指定用例时，报告应能看到对应的用例名。
- 文件改动后，之前版本的观察需要重新验证。缺少证据时，目标会在剩余预算内继续尝试。若验收模型配置缺失或调用失败，先修复配置，再输入 `/goal resume`。
- 会话意外退出后，重新打开同一会话，输入 `/goal` 可查看中断阶段。输入 `/goal resume` 会接着原来的轮次执行。若仅验收中断，会先重试验收。
- 目标可以调用 `run_subagent`。暂停会中断仍在执行的子任务，已完成的交接记录保存在会话中。恢复后，主代理可以再次委派并使用新取得的证据。
- 审批过程中可在 Web 确认框点击「暂停目标」，终端确认框可按 Ctrl+C。恢复后，仍需授权的操作会再次请求确认。
